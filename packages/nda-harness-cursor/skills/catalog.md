# Skills hub

This folder is the source Skills hub for NDA Harness. Native plugins bundle it once alongside the shared engine; do not copy shared skills into each project's `.nda-harness/`. The catalog is discovery metadata; load a skill body only for the assigned task. These skills are instructions, not installed tools or enforced gates.

| Skill | Select when | Required context | Output |
| --- | --- | --- | --- |
| [UI/UX Pro Max](ui-ux-pro-max/SKILL.md) | Designing, changing, or evaluating interfaces or user interactions, including accessibility | Approved UI scope/spec, existing design system, detected stack, relevant local files | UI/UX recommendations or scoped changes, using bundled search data |
| [Official Vietnamese document wording](vietnamese-official-wording/SKILL.md) | Drafting, revising, translating into Vietnamese, or reviewing wording for formal organizational communication or administration | Document purpose/audience, approved template/glossary, source facts | Vietnamese draft/revision and unresolved factual fields; human approves issuance |
| [Vietnamese tech writing](vietnamese-tech-writing/SKILL.md) | Drafting, revising, translating into Vietnamese, or reviewing engineering or product content, including interface messages | Document type and audience, source facts | Vietnamese technical or product draft and unresolved factual fields |
| [Diagram Design](diagram-design/SKILL.md) | Creating, modifying, or evaluating architecture, workflow, sequence, or other explanatory diagrams | Verified source relationships, audience, output requirements, approved project style | Self-contained HTML/SVG diagrams; PNG/SVG exports when requested |

Catalog schema version 2 provides a concrete question and positive/negative criteria for each specialist. Classify the current assignment's agreed deliverables; do not invent optional diagrams, interface changes, or writing tasks. Architecture discussion, reading a diagram as background, backend work supporting a UI, or ordinary Vietnamese chat alone does not qualify. A Vietnamese engineering RFC is technical content even when used internally. Missing inputs or approvals affects execution readiness, not whether the skill applies.

The local Jev helper reads [`catalog.json`](catalog.json) and selects zero or more of these skills. When no OpenRouter key is saved, the running coding agent answers those same questions and the helper stores the model name `local-agent`. The coordinating agent loads only the bodies that helper returns. Default to one skill for a specialist sub-agent. A UI assignment selects UI/UX Pro Max; a Vietnamese formal-document assignment selects the wording skill; a Vietnamese technical or product document selects Vietnamese tech writing; an explanatory diagram assignment selects Diagram Design. Select multiple only when the assignment needs them, such as Vietnamese wording within a diagram. Ordinary backend or test-review work may need none. Do not preload the whole hub into the coordinator or every child.

Agent capability checks, context preparation, and test-quality review are harness workflow improvements, not hub skills. They apply independently of specialist skill selection; see the [architecture](https://github.com/pilacorp/nda-harness/blob/dev/docs/architecture.md#harness-quality-improvements).

Context7 is a mandatory documentation tool outside the specialist hub. Make it available when library/framework documentation is needed; selection of no specialist skill does not remove that requirement. Query only relevant public documentation, with no private code/context or full documentation preload.

UI/UX Pro Max is vendored from NextLevelBuilder with its license and [pinned provenance](ui-ux-pro-max/SOURCE.md). The Vietnamese wording skill is locally authored and follows supplied organizational templates; it does not claim official certification or legal compliance. Vietnamese tech writing is vendored from trussary/vietnamese-language-skill with its license and [pinned provenance](vietnamese-tech-writing/SOURCE.md). It keeps English engineering terms and does not replace the official-document skill.

Diagram Design is vendored from Cathryn Lavery with its license, third-party notices, and [pinned provenance](diagram-design/SOURCE.md). It includes type references, templates, and local verification helpers. Load the selected type's references rather than the entire collection; retain the project's approved style choice.

Before spawning, provide a bounded assignment with: task/issue, allowed scope and side effects, repository revision, shared policy/profile paths, exact selected skill paths and pinned release revision, relevant input references, expected output, and stop conditions. Start with fresh/minimal context where the client supports it. A child loads the shared policy/profile and selected bodies, not the entire hub or unrelated parent history. Never pass credentials or personal-memory content to another agent.

Use the folder names `ui-ux-pro-max`, `vietnamese-official-wording`, `vietnamese-tech-writing`, and `diagram-design` as stable selection IDs; an empty selection is valid. Read this catalog for discovery, not the linked bodies. Validate IDs and resolved paths against the pinned hub before delegation. Record the IDs, catalog revision, short reason, and requested tools inline in task state. Load selected references progressively. Native startup/delegation hooks may automate this contract after client verification; tool-schema exposure must be verified separately from skill loading. Mandatory Superpowers/RTK requirements remain outside specialist selection.

Use the existing client's native delegation mechanism. If the client cannot isolate instructions or supports no sub-agents, use a separate fresh session with the same bounded assignment; document that limitation rather than claiming isolation. Skills do not grant new tools, permissions, human approvals, or authority to skip workflow gates. Returned findings are evidence for the coordinator and human reviewer, not approval.

Record selected skill paths/revision and assignment scope in the task record. On handoff, select again for the new assignment; do not accumulate every previously used skill. Maintainers review skill changes with the policy and pin them to the same release.
